# Services read UM sessions through sessionclient

Extends [ADR-0003](./0003-pharmacy-reads-um-sessions-from-redis.md) from the pharmacy API to every service that accepts UM tokens (pos, alert, snook, gold-shop). They all share UM's Redis instance, so each confirms the token's session by reading `session:<jti>` rather than trusting the JWT until it expires. The reader lives in UM as the `github.com/app-devper/um-api/sessionclient` module, which UM's own tests use to read what UM writes, so the key layout has one owner and one implementation. A service turns the check on by setting `UM_REDIS_HOST`; unset, it keeps its previous behaviour. When the store cannot answer and no confirmation is cached, safe methods (GET, HEAD, OPTIONS) continue under the signed token and writes are refused with 503. The pharmacy API keeps its stricter per-route policy from its own ADR.
